## ✅ REQUIREMENTS (MUST)

### Design Principles

- [ ] MUST prioritize **user wellbeing over engagement**
  - Success metric: User completes their goal and feels good
  - NOT: User spends maximum time in app
  - NOT: User returns as many times as possible

- [ ] MUST provide **full transparency about what TubieTools does**
  - Users understand EXACTLY what data is collected
  - Users understand HOW their data is used
  - Users can see WHY we ask for permission
  - No hidden terms of service
  - No dark patterns

- [ ] MUST allow **easy exit and data removal**
  - Users can delete their account anytime
  - Users can download their data anytime
  - Users can request permanent deletion
  - Account deletion = NO begging/retention attempts
  - Export must be in standard, usable format

### Prohibited Addictive Patterns

- [ ] MUST NOT use **infinite scroll**
  - Medical apps need boundaries, not endless browsing
  - Caregiver workflows need completion, not rabbit holes
  - Infinite scroll is designed to prevent stopping
  - Exception: Medical feeds MUST stop at appropriate place

- [ ] MUST NOT use **autoplay or auto-advance**
  - Video content can be watched only if user clicks play
  - NO auto-next-video (like YouTube)
  - NO auto-playing next reminder
  - Users deliberate about next action
  - Exception: Critical medical alert can't be auto-played (must be actively triggered)

- [ ] MUST NOT use **variable rewards (slot machine mechanics)**
  - NO loot boxes
  - NO random rewards
  - NO "streak" notifications (Snapchat model)
  - NO surprise notifications timed for addiction
  - NO reward timers that create urgency
  - Caregiver shouldn't gamble with care—care is reliable

- [ ] MUST NOT use **fear of missing out (FOMO)**
  - NO "limited time offers"
  - NO "expires today" urgency tactics
  - NO "only X people have done this" comparison
  - NO social pressure notifications
  - NO "you're falling behind" messages
  - Exception: Genuine medical alerts (medication due in 30 min) are NOT FOMO

- [ ] MUST NOT use **artificial urgency**
  - NO countdown timers on non-urgent features
  - NO "hurry, spots filling up"
  - NO flash sales or time-pressure
  - Exception: Real medical deadlines (med due, appointment time) require timers

- [ ] MUST NOT use **notifications for engagement (only for safety)**
  - NO notification badges (the red number)
  - NO notifications to get user back in app
  - NO notification spam
  - ONLY notifications for: Medical necessity, safety alert, critical information user requested
  - User MUST be able to disable 95% of notifications

- [ ] MUST NOT use **social comparison**
  - NO leaderboards
  - NO "# users have already done this"
  - NO "better than X% of users"
  - NO public profiles showing metrics
  - NO "friend comparison" features
  - Medical care is private; never compare users publicly

- [ ] MUST NOT use **gamification for retention**
  - NO points/badges/achievements for engagement
  - NO levels to unlock
  - NO daily login bonuses
  - Exception: Legitimate progress (child's medication adherence) can track, but NEVER for user engagement

- [ ] MUST NOT create **artificial scarcity**
  - NO "only 3 spots left"
  - NO "selling out"
  - NO "premium features" locked behind engagement
  - NO "unlock by sharing with friends"
  - Digital products are abundant; don't create false scarcity

- [ ] MUST NOT use **social sharing for virality**
  - NO "share to unlock feature"
  - NO "invite friends to gain access"
  - NO "share on social media" buttons on medical data
  - NO viral mechanics
  - Exception: User CHOOSES to share health wins (child's progress)

### What We DO Instead

- [ ] MUST provide **clear, honest value**
  - Product does ONE thing really well
  - User understands benefit immediately
  - No hidden complexity
  - Simplicity is the goal

- [ ] MUST design for **completing the task, then stopping**
  - Quick workflows (5 minutes max)
  - Clear endpoint/completion
  - User exits feeling accomplished
  - Staying too long is NOT success

- [ ] MUST provide **respectable friction**
  - Good friction: Confirming medication administration (prevents error)
  - Bad friction: Mandatory video before accessing feature (engagement trick)
  - Friction ONLY for safety, accuracy, or ethical reasons
  - NOT for engagement

- [ ] MUST enable **full user control**
  - User sets their own schedule (not app-driven)
  - User controls all notifications
  - User can opt into features (not trapped)
  - User can pause/stop anytime
  - NO "sticky" defaults that require work to turn off

- [ ] MUST design for **caregiver wellbeing**
  - Burnout risk: App demands too much attention
  - Exhaustion risk: Notifications interrupt sleep
  - Stress risk: App creates anxiety (competitive metrics)
  - App reduces burden, never adds to it

- [ ] MUST support **meaningful work**
  - Features solve real problems (administering meds, tracking health)
  - UI supports fast, accurate work (not slow/confusing)
  - Data presentation supports decision-making
  - NOT entertainment or procrastination

- ❌ Infinite scroll on content feeds
- ❌ Auto-play of videos or content
- ❌ Streaks or login bonuses
- ❌ Reward notifications (red badge numbers)
- ❌ Countdown timers on non-critical features
- ❌ "Only 3 spots left" scarcity messaging
- ❌ Comparison with other users
- ❌ Points/badges/levels for using features
- ❌ "Share to unlock" mechanics
- ❌ FOMO-based messaging
- ❌ Dark patterns hiding deletion option
- ❌ Notifications outside user's explicit opt-in
- ❌ "You're falling behind" messages
- ❌ Autoplay reminder sequences
- ❌ Slot-machine random rewards
- ❌ Artificial time pressure on non-medical features
- ❌ Public leaderboards comparing users
- ❌ Sticky defaults (must opt-in, not opt-out)
- ❌ Making it easy to purchase, hard to unsubscribe
- ❌ Targeting vulnerable populations (especially children)

## 📊 SOCIETAL BETTERMENT MATRIX

**Every feature must pass this matrix BEFORE coding.**

### Dimension 1: User Wellbeing
```
Question: Does this feature improve user's life quality?

Score 5: ✅✅✅ Reduces stress/burden/anxiety
Score 4: ✅✅   Solves a real problem
Score 3: ✅    Neutral (doesn't harm)
Score 2: ⚠️    Creates minor burden/confusion
Score 1: ❌    Creates significant burden
Score 0: 🚫   Exploits users

Minimum: Score 3 (neutral, no harm)
Target: Score 4-5 (improves wellbeing)
Reject: Score 0-2
```

### Dimension 2: Societal Impact
```
Question: Does this feature contribute to a better society?

Score 5: ✅✅✅ Enables people to help each other
Score 4: ✅✅   Solves a collective problem
Score 3: ✅    No negative societal impact
Score 2: ⚠️    Small negative impact (minor privacy concern)
Score 1: ❌    Moderate negative impact (exploitation)
Score 0: 🚫   Extreme negative impact (harms society)

Minimum: Score 3 (socially neutral)
Target: Score 4-5 (benefits society)
Reject: Score 0-2
```

### Dimension 3: User Autonomy
```
Question: Does this feature respect user choice and control?

Score 5: ✅✅✅ User fully in control, clear choices
Score 4: ✅✅   User can control most aspects
Score 3: ✅    Some defaults, easy to change
Score 2: ⚠️    Sticky defaults, hard to opt-out
Score 1: ❌    User trapped, limited choices
Score 0: 🚫   Manipulative, user has no choice

Minimum: Score 3 (easy to change)
Target: Score 4-5 (full user control)
Reject: Score 0-2
```

### Dimension 4: Honesty
```
Question: Is this feature transparent and honest?

Score 5: ✅✅✅ Purpose clear, data use transparent, no surprises
Score 4: ✅✅   Mostly clear, one area needs explanation
Score 3: ✅    Generally clear, some complexity
Score 2: ⚠️    Unclear purpose, some hidden mechanics
Score 1: ❌    Deceptive, hidden data practices
Score 0: 🚫   Deliberately misleading

Minimum: Score 3 (some clarity)
Target: Score 4-5 (completely transparent)
Reject: Score 0-2
```

### Dimension 5: Vulnerability Protection
```
Question: Does this feature protect vulnerable users (especially children)?

Score 5: ✅✅✅ Actively protects (prevents abuse)
Score 4: ✅✅   Protects from most exploitation patterns
Score 3: ✅    No special exploitation risks
Score 2: ⚠️    Some risk to vulnerable users
Score 1: ❌    Targets vulnerable users for engagement
Score 0: 🚫   Directly exploits vulnerable users

Minimum: Score 3 (no added vulnerability)
Target: Score 4-5 (active protection)
Reject: Score 0-2
```

## 🔍 VERIFICATION METHOD

### Pre-Implementation Audit

```
1. FEATURE DESCRIPTION AUDIT
   ☐ Feature has clear, single purpose
   ☐ Solves identified user problem
   ☐ Addresses caregiver/family need
   ☐ NOT designed for "engagement"

2. SOCIETAL IMPACT MATRIX
   ☐ Wellbeing: Score ≥ 3
   ☐ Society: Score ≥ 3
   ☐ Autonomy: Score ≥ 3
   ☐ Honesty: Score ≥ 3
   ☐ Vulnerability: Score ≥ 3
   ☐ Overall: Score ≥ 15

3. DARK PATTERN SCAN
   ☐ No infinite scroll
   ☐ No autoplay
   ☐ No streaks/login bonuses
   ☐ No badge notifications
   ☐ No countdown timers (except medical)
   ☐ No FOMO messaging
   ☐ No artificial scarcity
   ☐ No gamification for retention
   ☐ No social comparison
   ☐ No "share to unlock"

4. NOTIFICATION AUDIT
   ☐ Notifications only for: Medical need, safety, user-requested info
   ☐ NO engagement-based notifications
   ☐ User can disable all but medical
   ☐ NO notification spam
   ☐ NO auto-triggering sequences

5. USER CONTROL AUDIT
   ☐ User can opt-in (not opt-out)
   ☐ User can pause
   ☐ User can stop anytime (no penalty)
   ☐ User can delete data/account
   ☐ Deletion is easy (not buried in settings)
   ☐ Deletion is permanent (not hidden "recovery")

6. VULNERABILITY AUDIT (If vulnerable users involved)
   ☐ Feature does NOT target children for engagement
   ☐ Feature does NOT exploit medical condition
   ☐ Feature does NOT create anxiety/pressure
   ☐ Feature does NOT manipulate decision-making
   ☐ Feature DOES respect cognitive/physical limitations
```

### Post-Implementation Testing

```
USER TEST: "Can a user complete their task and feel good?"
   - User completes task in reasonable time
   - User feels accomplished, not drained
   - User willingly exits (not tempted to stay)
   - User returns because value, not addiction
   Result: PASS / FAIL

DEVELOPER TEST: "Is there any pressure to stay?"
   - Read code specifically looking for engagement hooks
   - grep -r "streak\|reward\|engage\|retention" 
   - Any results = Review for removal
   Result: PASS (zero engagement code) / FAIL (contains hooks)

CAREGIVER FEEDBACK: "Does this help or hurt your life?"
   - Parent with disability: Does this make care easier?
   - Exhausted caregiver: Does this drain you?
   - Overwhelmed family: Does this reduce stress?
   - Vulnerable child: Is this safe?
   Result: PASS (helps) / FAIL (hurts or exploits)

METRICS AUDIT: "What are we measuring?"
   - Success metrics: ✅ Time saved, Accuracy, Life quality
   - Rejected metrics: ❌ Daily actives, Session time, Engagement, Screen time
   Result: PASS (ethical metrics) / FAIL (engagement-based)
```

## 🚨 IF STANDARD VIOLATED

### Level 1: Design Phase
```
If feature includes dark patterns:
1. Designer flags violation in design doc
2. Product owner acknowledges (in writing)
3. Feature redesigned to remove addiction mechanics
4. No code written until design approved
5. Documented: When found, why added, how fixed
```

### Level 2: Code Review Phase
```
If code implements dark patterns:
1. Reviewer identifies specific violation
2. Code review blocked with explanation
3. Specific dark pattern link provided: example, harm, redesign option
4. Developer required to remove pattern
5. Cannot merge until clean
6. Team learning: Was pattern added intentionally? By mistake?
```

### Level 3: Production Phase
```
If abuse pattern reaches users:
1. EMERGENCY: Feature disabled immediately
2. Postmortem: How did this pass review?
3. User communication: Apology, explanation, fix timeline
4. Code audit: Does this pattern exist elsewhere?
5. Training: Team education on this harm
6. Recovery: Users' trust rebuilt
```

### Level 4: Escalation
```
If same dark pattern repeats:
1. Pattern = project-level failure
2. Code audit across entire product
3. All instances removed
4. Team retraining required
5. Process redesign to prevent recurrence
6. External review (ethics audit)
```

## 🛡️ PROTECTING VULNERABLE USERS (Especially Children)
